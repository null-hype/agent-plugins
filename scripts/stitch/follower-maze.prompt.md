# Follower Maze — Ordered Routing

Developer tool interface for Follower Maze lesson expected-vs-actual verification within an IDE workbench adhering to the Pre-cog Telemetry IDE design token set (DESIGN.md).

## Design System Tokens (Pre-cog Telemetry IDE)

- Surfaces: Obsidian canvas (surface `#0b141c`), container (`#182028`), elevated split (`#222b33`), outline borders (`#30363d`).
- Semantic Telemetry Palette:
  - Verified / Deterministic: `#3fb950`
  - Predictive / Analysis Focus: `#58a6ff`
  - Stale / Warning: `#d29922`
  - Alarm / Counterexample: `#f85149`
- Typography: Geist for UI headers and readouts; JetBrains Mono with tabular numbers (font-variant-numeric: tabular-nums) for editor text, gutters, line numbers, squiggles, CodeLens rows, and telemetry data.

## Workbench Structure

- Top status line:
  - Header readout displaying persistent axiom indicator `followerMaze.orderedRouting` in solid verified state.
  - Counter footer readout: `4 pass · 12 missing · 4 forbidden · 4 both`
- Editor view (Permutation Stream):
  - Monaco editor model with line numbers and a gutter displaying 24 lines representing the full 24-permutation family of the 4 events (`1|F|10|20`, `2|S|20`, `3|U|10|20`, `4|S|20`) over world connected `{10, 20}`:
    - 4 passing lines (`1234`, `3412`, `4123`, `4312`) displaying clean text with verified `#3fb950` status tags.
    - 12 lines failing missing delivery (`1324`, `1342`, `2134`, `2341`, `2413`, `2431`, `3241`, `3421`, `4132`, `4213`, `4231`, `4321`): each carrying a red squiggle from setModelMarkers at Error severity with marker code `fm-missing-delivery`. Each has a CodeLens row directly above the line titled `✗ fm-missing-delivery · 1 related`.
    - 4 lines failing forbidden delivery (`1243`, `1423`, `3124`, `3142`): each carrying a red squiggle from setModelMarkers at Error severity with marker code `fm-forbidden-delivery`. Each has a CodeLens row directly above the line titled `✗ fm-forbidden-delivery · 1 related`.
    - 4 lines failing both (`1432`, `2143`, `2314`, `3214`): carrying squiggles for both divergences, with a CodeLens row above titled `✗ fm-missing-delivery · 2 related`.
  - Hovering a failing line displays an inline hover carrying the verdict and its evidence:
    `**fm-missing-delivery** seq=2 user=10 missing delivery`
    `_observation_ (followermaze-log.jsonl:2): event 2|S|20 not routed to user 10`
    `_axiom_ (followerMaze.orderedRouting): ordering errors surface as routing errors because follow-state is temporal`
  - Clicking the CodeLens row above line `[4,2,3,1]` opens an inline evidence widget (.evidence-widget) directly under that line, showing the competing evidence locations and supervisor repair choices:
    `[change world] [change model] [change axiom]`
- Secondary split view (Expected vs Witness Traces):
  - Left split: required trace (`20 <- seq 1`, `10 <- seq 2`).
  - Right split: witness trace generated by learner solve(), with warning indicator: "green here rules out nothing (1-in-6 coincidence)".

## Six Storyboard Frames

1. Frame 1 (render): World connected `{10, 20}` with arrival sequence `[1,2,3,4]`. Left split shows required trace (`20 <- seq 1`, `10 <- seq 2`). Right split shows witness trace empty ("awaiting solve()"). Header shows persistent axiom indicator `followerMaze.orderedRouting`.
2. Frame 2 (witness): Learner solve() output appears in right witness split, neutral and unevaluated (`20 <- seq 1`, `10 <- seq 2`).
3. Frame 3 (evaluate baseline): Baseline ordering `[1,2,3,4]` evaluated. Both trace rows show verified green `#3fb950`, accompanied by an amber warning notification line (`#d29922`): "green here rules out nothing" (passing baseline is a 1-in-6 coincidence).
4. Frame 4 (transform): Arrival ordering A over arrival ordering B, displaying "24 orderings of the same 4 events". Axiom indicator `followerMaze.orderedRouting` transitions to solid verified state.
5. Frame 5 (evaluate family): Editor surface presents a stream of 24 lines in a Monaco editor model with line numbers and a gutter, one line per arrival ordering of the 4 events. Evaluated by outcome: 4 lines pass, 12 lines squiggled with marker code `fm-missing-delivery` and CodeLens row `✗ fm-missing-delivery · 1 related`, 4 lines squiggled with marker code `fm-forbidden-delivery` and CodeLens row `✗ fm-forbidden-delivery · 1 related`, 4 lines squiggled for both divergences with CodeLens row `✗ fm-missing-delivery · 2 related`. Footer counter shows: `4 pass · 12 missing · 4 forbidden · 4 both`.
6. Frame 6 (open a failing world): Frames 5 and 6 are one CodeLens click apart. Clicking the CodeLens row `✗ fm-missing-delivery · 1 related` above failing ordering line `[4,2,3,1]` toggles the inline evidence widget (.evidence-widget) directly under that line, exposing the `fm-missing-delivery(seq=2, user=10)` diagnostic, related evidence rows, and supervisor repair choices: `change world / change model / change axiom`.
