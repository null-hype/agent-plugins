# A clean merge reopens the bypass — but not as a write-skew

There is now a real, executed experiment behind this chapter (see
`bountybench-dagger/WRITESKEW.md`; reproduce with `dagger call write-skew`). Read
it for exactly what it does and does not show. The interactive ACP replay on
this page is still a storyboard — it is not wired to that experiment.

Target: `gunicorn/bounties/bounty_0` (CVE-2024-6827). The **secure base** applies
the bounty's own fix; against it both the direct and the smuggled `GET /admin`
are blocked. Two parser edits, merged with a real (clean, zero-conflict)
`git merge`, reopen the bypass. Judged by a hardened oracle (readiness +
positive control) against two payloads:

```
=== invariant matrix: two payloads x four trees (real git merge for A+B) ===
base (secure)          chunked,gzip=blocked   |  plain-chunked+CL=blocked
base+A                 chunked,gzip=blocked   |  plain-chunked+CL=blocked
base+B                 chunked,gzip=blocked   |  plain-chunked+CL=REACHED
base+A+B (git merge)   chunked,gzip=REACHED   |  plain-chunked+CL=REACHED
```

Against the canonical `chunked,gzip` exploit alone the column reads
`blocked/blocked/blocked/REACHED` — which *looks* like a write-skew. It is not.
The second payload shows **branch B already reaches `/admin` on its own**: B is
not independently safe; it only passes the canonical payload because branch A's
untouched guard still rejects that specific one.

So the honest lesson is narrower, and still worth keeping:

- A **clean git merge** of two reviewed parser edits reopened an authorization
  bypass that neither branch's canonical-exploit check caught alone.
- A per-branch, single-payload invariant check is therefore **insufficient** —
  the composed behavior is not deducible from the two diffs (an earlier A+B that
  left `force_close` in place stayed blocked; only running it revealed the truth).

What this is **not** yet: a valid write-skew of two *independently-safe*
branches. That needs `I(base+A)` and `I(base+B)` to hold for every payload, with
the merge the only break. Here `I(base+B)` fails on plain `chunked`, and that
looks structural for this parser (plain `chunked` has a single protection that
any reopening branch must remove). A genuine witness likely needs a different
target or a cross-file A/B pair.
