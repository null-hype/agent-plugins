# Ghost Trace Machine: the first turn

This part is one recorded conversation between a client and an agent over
the Agent Client Protocol (ACP). This lesson is its first turn: the client
has already sent a prompt, and the agent's reply is recorded but hidden
until you press Solve.

**The problem being diagnosed.** Follower Maze is a small event-delivery
system: events arrive out of order, each with a sequence number, and some of
them must be delivered to particular users. A system that applies each event
the moment it arrives, rather than in sequence order, can silently drop a
delivery. The question below asks why user 10 never received one.

### The request already sent

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "session/prompt",
  "params": {
    "sessionId": "sess_ghost-01",
    "prompt": [{ "type": "text", "text": "Why didn't user 10 get the status update from arrival order 4,2,3,1?" }]
  }
}
```

The **Client** preview on the right shows this turn as a warm-log region,
blocked on the agent's reply. The **Agent** preview shows the same turn as
the raw envelope the agent process actually exchanges.

Press **Solve** to reveal the agent's recorded diagnostic response. Nothing

### One real Follower Maze case, not an invented one

The diagnostic this turn reveals is a real
[`GovernanceDiagnostic`](https://github.com/null-hype/null-hype.github.io/blob/main/tutorial-app/src/lib/governanceDiagnostic.ts)
-- `code`/`severity`/`message` about a `subject`, plus the `related` evidence
it was actually computed from, plus a stable `evaluationId` -- the same
shape [chapter 3's warm-log lesson](/part-1/chapter-3/lesson-4) and Follower
Maze both use, carried here in the ACP envelope's `result._meta.diagnostic`
instead of invented flat fields. It is not a stand-in "ledger conflict":
it is the real `check()`/`followerMazeAxiom()` verdict for one genuine
arrival ordering, `4,2,3,1`, against the "plausible wrong model" witness
(`arrivalOrderWitness`: apply each event the instant it arrives, instead of
in sequence order) -- the same functions and the same fixtures
[Follower Maze](https://github.com/null-hype/null-hype.github.io/blob/main/tutorial-app/src/lesson-farms/follower-maze/followerMaze.ts)
uses elsewhere in this app, run for real before this lesson's fixture was
written.

For this ordering, that witness really does drop a required delivery:

- required (sequence order): `20 <- seq 1`, `10 <- seq 2`
- what `arrivalOrderWitness` actually delivers: only `20 <- seq 1`
- `check()` flags: `fm-missing-delivery(seq=2,user=10)`

The **Client** preview draws this the same way the warm-log lessons do:
a real Monaco marker underlines the failing line, hovering it shows the
verdict and its related evidence, and a CodeLens toggles the same evidence
as a widget underneath the line -- not a plain printed message.

### Provenance

This exchange is fixture `ghost-trace-v1`, captured 2026-09-22. Both frames
are the literal JSON-RPC bytes from a real ACP client/agent exchange --
not hand-typed JSON authored to look like one, and the diagnostic inside
the agent's reply is the real output of a real computation, not a
hand-typed verdict either. `evidence/ghost-trace-v1/` (repo root of
`tutorial-app`) has the scripts that produced it: a minimal agent whose
diagnostic comes from running `followerMaze.ts`'s real `check()` over a
vendored copy of the real arrival/world fixtures, a client that drives the
exchange and taps the wire, the full raw transcript, and the exact command
to reproduce it -- re-running it is byte-identical apart from each frame's
`capturedAt`. This is a one-off evidence script, not a general recording pipeline.
That pipeline hasn't been built yet, but the fixture still has to come from
somewhere real.

### Extending this: a new lesson's own recording

`src/lib/acpTraceProtocol.ts`'s header comment is the contract for the next
lesson in this part: supply your own `_files`/`_solution` pair for
`custom.acpTrace.traceFile`, ending the starter file's `frames` array at
your breakpoint with a `nextTurn` naming who acts next, and the solution
file with that frame appended and `nextTurn: null`. `AcpTraceBridge` and
both preview pages need no lesson-specific code to pick that up.
