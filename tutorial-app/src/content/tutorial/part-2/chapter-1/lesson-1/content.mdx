# Ghost Trace Machine: the first turn

This part is one recorded ACP thread. This lesson is its first turn: the
client has already sent a prompt; the agent's reply is recorded but hidden
until you press Solve.

### The request already sent

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "session/prompt",
  "params": {
    "sessionId": "sess_ghost-01",
    "prompt": [{ "type": "text", "text": "Why did the last write to the ledger fail?" }]
  }
}
```

The **Client** preview on the right shows this turn as a warm-log region,
blocked on the agent's reply. The **Agent** preview shows the same turn as
the raw envelope the agent process actually exchanges.

<AcpTraceBridge client:load />

Press **Solve** to reveal the agent's recorded diagnostic response. Nothing
here calls a live agent -- Solve replays the exact envelope this lesson's
`_solution/acp-trace.json` already carries, the same `_files` -> `_solution`
swap every other TutorialKit lesson uses. Reload the page, or press
**Reset**, to return to the blocked state; replaying produces the same
result every time.

### Provenance

This exchange is fixture `ghost-trace-v1`, captured 2026-09-22. Both frames
are the literal JSON-RPC bytes from a real ACP client/agent exchange -- not
hand-typed JSON authored to look like one. `evidence/ghost-trace-v1/` (repo
root of `tutorial-app`) has the two scripts that produced it (a minimal
agent, a client that drives it and taps the wire), the full six-frame raw
transcript, and the exact command to reproduce it; re-running it is
byte-identical apart from each frame's `capturedAt`. This is a one-off
evidence script, not the deferred Playwright recording/reporter pipeline --
CIT-245 deferred building general recording capability, not the requirement
that a fixture actually come from somewhere real.

**Dagger Cloud trace link: not yet captured** (see `src/lib/acpTraceProtocol.ts`
for the `provenance.daggerCloudTraceUrl` field a real capture would fill in;
this fixture leaves it absent rather than link to one that doesn't exist).

### Extending this: a new lesson's own recording

`src/lib/acpTraceProtocol.ts`'s header comment is the contract for the next
lesson in this part: supply your own `_files`/`_solution` pair for
`custom.acpTrace.traceFile`, ending the starter file's `frames` array at
your breakpoint with a `nextTurn` naming who acts next, and the solution
file with that frame appended and `nextTurn: null`. `AcpTraceBridge` and
both preview pages need no lesson-specific code to pick that up.
