# Extend the investigation to a local image folder

The panel below is generated by executing the checker. It includes the original
canary, a freshly encoded 2×2 black PNG control, an SVG with active-content
patterns, an actual upstream Excalidraw export and a scene with a missing asset.
The fresh PNG is a local checker control; it is not presented as the exact
historical Rails PNG input.

The SVG check reports common script, event-handler and remote-reference
patterns. It is not an XML sanitizer and can miss other active content.
The Excalidraw check reads both legacy JSON and compressed scene metadata,
then reports referenced assets absent from its file map. An undecodable scene
is reported as an incomplete check. Present assets are not decoded or validated.

This separates two concerns from the library discussion: keeping the assets
together and handling their contents safely. Finding a missing asset helps with
the first. Neither that check nor the SVG pattern scan resolves the sanitization
question raised in the original issue.

Scene coordinates cannot be compared directly to PNG dimensions: exports have
their own scale, origin and padding. This checker makes no claim that the
embedded scene visually matches the rendered pixels.

A matching signature does not prove an image is valid. **No finding means only
that these particular checks found nothing.** It is not permission to trust or
share a file without further review.
