# What does the image check actually establish?

In the Rails/MATLAB investigation, an upload declared `image/png` reached
libvips' MATLAB loader. That loader and matio interpreted different parts of
the same header differently. The resulting HDF5 read returned bytes from a
test-owned dummy file through a Rails image variant.

We start with **the same canary bytes**, regenerated by that investigation's
`craft_mat_canary.py`. Their SHA-256 matches both retained MATLAB runs:
`f1c62ebc5fb7ab50655d505f3c30498713cdef232d3bdef585935024bd007fcc`.
Renaming the file `rails-canary.png` changes neither its bytes nor that identity.

## One file, two questions

**What claims do its bytes make?** The checker implements the existing
`CraftedMatFile` header predicates. The leading text selects libvips' `matload`,
while the version and endian bytes select matio's MAT 7.3/HDF5 reader. It reports
that disagreement even when the filename is `canary.mat`. A second, weaker
check notices that a file named `.png` lacks the PNG signature.

**What happened when Rails processed it?** That requires execution evidence.
The original investigation retained these four outcomes:

| Input | Untrusted loaders | Retained outcome |
| --- | --- | --- |
| MATLAB canary | Allowed | Variant returned the dummy file's bytes; trace recorded the file open |
| Same MATLAB canary | Blocked | Loader refused; no dummy file open |
| PNG control | Allowed | PNG variant succeeded; no dummy file open |
| Same PNG control | Blocked | PNG variant succeeded; no dummy file open |

The observations, source hashes, configuration identity and syscall traces live
in [the CIT-294 investigation](https://github.com/null-hype/agent-plugins/tree/main/docs/investigations/CIT-265/cit-294).
Its `Reconcile.pkl` and `cit294.test.pkl` check those retained observations.
Running today's image checker does **not** rerun Rails or establish that a
private file was read. The header finding is a reason to inspect loader policy.

This is why the control is to block untrusted loaders. Adding another file-type
opinion does not resolve the disagreement between downstream readers.

The SVG check reports common script, event-handler and remote-reference
patterns. It is not an XML sanitizer and can miss other active content.
The Excalidraw check reads both legacy JSON and compressed scene metadata,
then reports referenced assets absent from its file map. An undecodable scene
is reported as an incomplete check. Present assets are not decoded or validated.

Scene coordinates cannot be compared directly to PNG dimensions: exports have
their own scale, origin and padding. This checker makes no claim that the
embedded scene visually matches the rendered pixels.

A matching signature does not prove an image is valid. **No finding means only
that these particular checks found nothing.** It is not permission to trust or
share a file without further review.

## Run it on your files

From the repository's `tutorial-app` directory:

```sh
npm ci
npm run image-claims -- /path/to/downloaded-image.png /path/to/drawing.svg
```

The command reads local bytes without rendering the files. Exit status is
`0` for no findings, `1` for findings, and `2` for a usage or read error.

For the lesson's examples and reproducibility check:

```sh
npm run image-claims -- src/stories/fixtures/image-claims/rails-canary.png src/stories/fixtures/image-claims/control.png
npm run image-claims:check
npm run image-claims:render
```

The first command should report the canary and exit `1`. The second runs the
regressions and checks the displayed panel against a fresh execution; the third
regenerates it after an intentional change.

## Where Proton Drive fits

For an encrypted folder, these checks can run locally before upload or after
files are downloaded. The command above accepts those downloaded paths.
This PR demonstrates the local check; it does not perform a Proton Drive
login, download, upload, or automatic sharing decision. Preserving the original
bytes and the checker output lets a later investigation ask what was checked,
with which version, and what still needs evidence—just as the Rails case does.
