# CIT-294 review history `v1` evidence

CIT-306: the pinned sources behind the recorded history **#117 → review 1 →
#118 → review 2 → #120 → review 3 → #120 follow-up → merge**. The recording
that points into this directory is `src/lib/reviewHistory/`; the plain-language
account is `docs/review-history-walkthrough.md`.

This directory is evidence, not build infrastructure. Nothing in the app
imports or runs `collect.mjs`, and CI does not run it. The specs under
`src/lib/reviewHistory/` read the committed files here and check them without
git, so they work on any checkout. Bytes are bundled at their **exact
identities**; current `main` bytes are never substituted (for S1 to S3 they
differ from what is bundled, and after the lesson correction in this change
the lesson page differs from S3 and S4 too).

## Layout

| Path | What it is |
| --- | --- |
| `manifest.json` | The index: the five states with their commits, the bundled files with git blob id / sha256 / length, the captures with their origin. Generated by `collect.mjs`. |
| `files/<revision>/<repo path>` | The exact bytes git holds at that revision and path. Only what an evidence reference points at is bundled, once per revision. |
| `captures/` | Texts that are not a file at a revision: connector output, raw commit objects, and facts derived by the collector. |
| `collect.mjs` | The provenance tool: reads git objects, writes `files/`, the git-derived captures and `manifest.json`; `--verify` re-hashes everything without git history. |

## How each part was obtained, and how far to trust it

| Part | Obtained by | Re-derivable offline? |
| --- | --- | --- |
| `files/**` | `git cat-file blob <revision>:<path>`; `collect.mjs` asserts the blob id equals sha1 of the bytes | Yes: blob ids and sha256 are checked from the files alone |
| `captures/git-commit-object-<sha>.txt` | `git cat-file commit <sha>`: tree, parents, author, committer, message | Yes: sha1 of `commit <len>\0<bytes>` is the commit id |
| `captures/git-landing-facts.json` | git commands run by `collect.mjs` (ancestry, tree ids, lesson blobs, whether the tutorial page exists at each state) | With a full clone |
| `captures/linear-*.md` | Transcribed from Linear connector responses on 2026-10-04 | **No.** Re-fetch the comment or issue and diff |
| `captures/github-pr-*-body.md` | Transcribed from GitHub connector responses on 2026-10-04 | **No.** Re-fetch the PR and diff |
| `captures/api-landing-facts.json` | Copied from connector responses (PR merge times, issue completion times) | **No** |
| `captures/review-3-retrieval-check.json` | The searches made for review 3's text, and the empty results | **No**; it is a record of a negative result |

Notes on the connector texts:

- **Q0** (`linear-CIT-294-description.md`) is the issue description as retrieved

  2026-10-04T03:57:36Z). It may have been edited in between and Linear history
  was not consulted, so it is the text as retrieved, not proven to be the text

- **Review 1 and review 2** are the comment bodies as retrieved. Each comment

- Every capture is the connector's text plus one trailing newline.

## Verifying

```bash
node tutorial-app/evidence/cit-294-review-history-v1/collect.mjs --verify
cd tutorial-app && npx vitest run src/lib/reviewHistory
```

`--verify` re-hashes every file and capture, recomputes the commit-object ids,
and refuses unlisted files. `bundle.spec.ts` does the same independently, and
also checks that every range in the recording exists in the pinned bytes and
holds its verbatim anchor, that every quote is verbatim, that nothing is offered
before the thing it records exists, and (only where the commits are present
locally) that the bytes equal git's.

## Re-collecting

Needs a full clone. The reviewed commits are not reachable from `main`;
`collect.mjs` fetches them by full SHA from `origin` (`git fetch origin
<sha>`), which GitHub still serves. Re-running it must leave `manifest.json`
unchanged; a difference means a pinned revision or path changed.

## What is not here

Absence is recorded as absence, never filled in:

- **A sealed declaration** or any registration made before the run. Q0 is the
  issue text, not a declaration, and nothing here simulates a Register action.
- **A Proton Pass observation** or `PROTON_PASS_AGENT_REASON` for this run.
- **Review 3's original text.** The searches that found nothing are in
  `captures/review-3-retrieval-check.json`. The second-hand account is the
  `cc23e89` commit message and the `CIT-294.md` section "Strengthened per the
  CIT-303 PR follow-up review".
- **The output of the reviewers' mutation runs.** They were made in temporary
  copies; only the review prose records the results.
- **A retained check result at S1.** `reports/` does not exist until #118.
- **A report of the flags the mutations raise.** `reports/diagnostics.json` is
  an empty list for every arm at S2, S3 and S4, and is byte-identical across
  the three; the flags the mutations raise are asserted in `cit294.test.pkl`
  and listed as passing in the JUnit report, but never retained on their own.
- **Any review of S4**, the final revision.
- **The pre-rewrite S3 and S4 commits.**
