# CIT-281: fixture cleanup from the CIT-280 review

Applies the fixture changes the [CIT-280 review](../CIT-265.md) asked for. No
new containers were built and nothing was re-run: this is a rework of the
committed fixtures and a format conversion of an already-committed diff.
Fixtures touched: [`fixture-active-storage.json`](./fixture-active-storage.json),
[`fixture-negative-control.json`](./fixture-negative-control.json). New
artifact: [`cit-277/restic-diff-before-to-after.jsonl`](./cit-277/restic-diff-before-to-after.jsonl).

## What the review asked for, and what was done

| Review item | Change |
| --- | --- |
| Level-0 `diff_items` carry package name and version only, no summaries | Both fixtures' `diff_items` now hold `{component, kind, from_version, to_version}` with **no `summary` field**. The old placeholder allowed a `summary` "from release notes/commit bodies" -- that line is the level-3 hint, so it is gone, and a rule now says so. |
| `files` holds the full `new_framework_defaults_7_0.rb` instead of hand-picked files | The positive fixture's `files` is now exactly `{ "config/initializers/new_framework_defaults_7_0.rb": <full generator output> }`, verbatim from CIT-277's `after` tree. The old rule ("the Active Storage code that hands uploads to the image processor, and the config that selects vips") pre-selected the two answer-bearing files; it is replaced. |
| Filter restic noise (logs, sqlite, bootsnap caches, bundler compact index) | Captured as a `jq` expression (below), applied over the JSONL. |
| Store CIT-277's restic diff as JSON Lines, converting the committed text diff | `cit-277/restic-diff-before-to-after.jsonl` created by converting the committed `restic-diff-before-to-after.txt` -- not by rebuilding the containers. Same shape as CIT-272's JSONL. |
| `state_source` is CIT-272 + CIT-277 | Both fixtures' `meta.state_source` now reads `CIT-272 + CIT-277` (positive) / `CIT-272 + CIT-277, variant_processor pinned to :mini_magick` (control). Was the stale `CIT-270 snapshot diff (NOT YET RUN ...)`. |
| Negative control is the same CIT-277 upgrade with `variant_processor = :mini_magick` pinned | The negative control was rebuilt as a **matched** control (see below). |

## Level-0 `diff_items`: how the 20 items were derived

`state_source` is **CIT-272 + CIT-277**, so the level-0 state unions two
snapshot diffs at the package (resolved-version) level, which is the unit
CIT-265's method names ("resolved dependency versions"):

- **From CIT-272** (libvips system package, built from source): one item,
  `libvips 8.12.2 -> 8.13.0`. This is the release that first carries the
  untrusted-operations flag.
- **From CIT-277** (in-place Rails upgrade), from the two committed
  `Gemfile.lock` files' resolved top-level specs: **14 changed** (the Rails
  stack `6.1.7.10 -> 7.0.10` plus `jbuilder 2.13.0 -> 2.15.1`) and **5 added**
  (`benchmark`, `bigdecimal`, `drb`, `mutex_m`, `securerandom` -- activesupport
  7.0's new default deps).

Total: **20 items**. The image stack (`image_processing 1.14.0`,
`mini_magick 4.13.2`, `ruby-vips 2.3.0`) is unchanged across the upgrade and
so is not in `diff_items`. Transitive gems that appear as *new dependency
lines* in the raw lock diff (`net-imap`, `net-pop`, `net-smtp`, `racc`,
`base64`, `logger`, ...) were already present at identical resolved versions
before and after, so they are not version changes and are excluded.

The single load-bearing file for the detector -- whether a fresh agent or Jev
reads the commented-out `variant_processor = :vips` line among ~20 other
commented default flips rather than skimming past it -- is the full
`new_framework_defaults_7_0.rb` in `files` (line 71 of the embedded copy).
`diff_items` deliberately does **not** flag it.

## The noise filter (`jq`)

`restic-diff-before-to-after.jsonl` is the faithful, unfiltered conversion of
the committed text diff (3,152 `change` lines + one `statistics` line). Noise
is removed with this expression, recorded here so the filter is auditable and
reproducible rather than baked destructively into the artifact:

```
jq -c 'select(.message_type=="change")
       | select(.path
           | test("^/app/log/|\\.sqlite3$|^/app/tmp/cache/bootsnap/|^/root/\\.bundle/cache/compact_index/")
           | not)' \
  cit-277/restic-diff-before-to-after.jsonl
```

It drops **820** entries and leaves **2,332**:

| Category | Path pattern | Entries removed |
| --- | --- | --- |
| Rails logs | `^/app/log/` | 1 |
| SQLite databases | `\.sqlite3$` | 2 (`development.sqlite3` changed, `test.sqlite3` added) |
| bootsnap caches | `^/app/tmp/cache/bootsnap/` | 816 (compile-cache-iseq + load-path-cache) |
| bundler compact index | `^/root/\.bundle/cache/compact_index/` | 1 |

The 816 bootsnap entries are why the filter matters: the review saw only 6 of
them because it counted the 25 *changed* files, but the *added* set contains
~800 more iseq cache entries. After filtering, the meaningful in-place
`/app` edits are the 14 config/`bin`/`Gemfile`/`schema` files the review
expected (`config/application.rb` -- the `load_defaults` line -- among them),
plus the new `new_framework_defaults_7_0.rb` and the vendored 7.0 gem trees.

### JSONL conversion note

Each text-diff line `M    /path` (modifier char, four spaces, path) maps to
`{"message_type":"change","path":"/path","modifier":"M"}`; modifiers `+`/`-`/`M`
carry over unchanged, matching CIT-272's JSONL. The trailing `statistics` line
is synthesised from the text diff's footer: all count fields (`2631 new`,
`0 removed`, `25 changed`, `496` dirs, `1993`/`23` data blobs, `5073`/`4577`
tree blobs) are verbatim; `source_snapshot`/`target_snapshot` come from the
header (`d34af4dc` -> `2834abf1`). The only imprecise fields are `added.bytes`
/ `removed.bytes`: restic's text footer recorded totals only to `MiB`
(`31.004` / `15.177`), so those bytes are derived from the MiB figures and are
accurate to ~±0.0005 MiB, not exact. Everything else is a lossless
transcription of the committed text diff.

## The matched negative control

The old negative control was a libvips-release diff with no loader/trust
change (CIT-272-shaped). The review's objection: the positive is a
Rails-*upgrade* diff and the old control was a libvips-*release* diff, so Jev
could separate them **by the kind of diff alone**, not by reasoning about the
processor.

The rebuilt control removes that confound. It is the **same CIT-272 + CIT-277
state** as the positive, with one difference: an active line pinning the
processor back to the pre-upgrade backend,

```ruby
Rails.application.config.active_storage.variant_processor = :mini_magick
```

carried in `files["config/initializers/active_storage_variant_processor.rb"]`.
Its `diff_items` are **byte-identical** to the positive fixture's (verified with
`jq -S`), and it contains the same libvips 8.13.0 change. The two states differ
only in whether uploads are routed through libvips' untrusted loaders. So a
model that scores the positive high and the control low is discriminating on
the composition; a model that scores both the same is reacting to "vips and
uploads sound risky" regardless of the live processor -- the exact
no-discrimination outcome the review named as grounds to abandon the thesis.
