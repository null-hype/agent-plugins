## 3. Vocabulary

Implementation, evidence and row status are tracked separately, so a working interaction can show
recorded evidence.

| Column | Values |
| --- | --- |
| Surface | **TK** TutorialKit lesson · **SB** Storybook story · **none** |
| Implementation | **working** (runs and responds today) · **stubbed** (renders, but input or data is fixed) · **missing** |
| Evidence | **captured execution** (output of a real run) · **live computation** (a real checker run in the browser over a fixture) · **recorded prose** (real review or PR text, not an execution) · **authored illustration** (hand-written; labelled as such) · **not available** |
| Disposition | **reuse** · **adapt** · **missing** · **deliberately deferred** |
| Row status (transition table, the issue's terms) | **working** · **recorded replay** · **missing** |

"Live computation" and "recorded prose" are added to the three evidence classes suggested in the
CIT-304 thread: a checker run live over an authored fixture is neither a captured run nor an
illustration, and a review is real and dated but not an execution.

Two distinctions the rest of the document depends on:

- **Navigating a recorded state vs exploring an alternative.** Selecting `baseline` or `patched` in
  the Jev viewer, or a recorded commit, shows what was recorded. Choosing a different premise or a
  hypothetical commit shows what *would* differ. The first exists; the second does not.
- **Recorded vs post hoc.** Anything the reader adds after a recorded run is *post hoc*. It is never
  sealed, never styled as a prediction, and never placed before the run it concerns.

### Invariants to preserve

- Input, monitor, diagnostic and each verdict channel stay separate; a model score, an executed check
  and an authority decision never share one pass/fail badge.
- Recorded, scripted, simulated and post hoc material keeps its label; nothing invents a timestamp,
  trace link, seal or Git hash that was not recorded.
- The original failure stays visible after a repair, and a pin is never edited, only superseded.
- Typed input becomes typed records; nothing downstream compares strings to an expected reason.
- "Not scored" or "pending" is shown before a recorded result is revealed.
- Absence is shown as absence ("not captured", "not sealed before this run"), never filled in.
- The viewer observes a recorded turn; navigation must not look like an agent action (CIT-251, CIT-298).
