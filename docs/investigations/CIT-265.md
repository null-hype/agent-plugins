# CIT-265: Rails composition-bug detector, verified against CVE history

Parent spike: enumerate candidate composition vulnerabilities in Rails, using
Rails CVE history as blind verification. First case: **CVE-2026-66066**
(Active Storage + libvips, [GHSA-xr9x-r78c-5hrm](https://github.com/advisories/GHSA-xr9x-r78c-5hrm)).

This pass covers [CIT-273](#cit-273-training-cutoffs-vs-disclosure-date)
(training-cutoff gate), [CIT-274](#cit-274-expected-jev-vector) (pre-registered
Jev vector), and CIT-270 (the Rails 6.1.7-to-7.0.0 snapshot diff — see
[`CIT-265/CIT-270.md`](./CIT-265/CIT-270.md)), per the parent issue's own
"Open: contamination" question and CIT-255's requirement to seal predictions
before execution. CIT-271, 272, 275, and 276 remain **NOT RUN**: 271 and 275
depend on this pass's outputs but weren't run themselves (271 needs a
genuinely fresh-context agent, not this session; 275 needs a typesafe.ai
client that doesn't exist yet); 272 needs a *different* fixture image that
actually installs libvips, which CIT-270's build deliberately does not.

**CLAUDE.md's `bountybench-dagger-*` roles/delegation section does not govern
this work** — its scope is explicitly directories matching that name. No
container-use environment was created, and nothing here touches
`pending-agent-prs.json` or the bountybench-loop supervisor.

## CIT-273: training cutoffs vs. disclosure date

CVE-2026-66066's disclosure date: **2026-07-29** (per the issue). Technical
details were withheld until 2026-08-28, per the advisory.

| Model | Role in spike | Published cutoff | vs. disclosure (2026-07-29) |
| --- | --- | --- | --- |
| Claude Sonnet 5 | free agent (CIT-271), supervisor-class work generally | January 2026 | ~7 months **before** |
| Claude Opus 5 | advisor / stronger-judgment calls | May 2026 (officially); independent probing suggests actual knowledge tracks closer to the Jan 2026 Sonnet/Fable cutoff | ~2 months **before** (officially) |
| Jev (TypeSafe, backs the Noul triage questions) | triage judge (CIT-275/276) | **Not published.** TypeSafe's own announcement (typesafe.ai/blog) is dated 2026-09-27 and says Jev is "available today in early access"; some secondary sources (aggregator blog posts, not typesafe.ai) instead give a 2026-09-15 launch date. Primary source preferred here; the discrepancy is unresolved and not investigated further in this pass. Either date, no training-data range or cutoff is disclosed on any source checked. | **Unknown** — see below |

Sources: [GHSA-xr9x-r78c-5hrm](https://github.com/advisories/GHSA-xr9x-r78c-5hrm);
[typesafe.ai/blog: Introducing System One Models & Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev);
[docs.typesafe.ai](https://docs.typesafe.ai).

**Reading this table:** Sonnet's and Opus's official cutoffs both predate
disclosure, which is the *weak* form of good news — it means neither model
could have trained on the CVE writeup, GHSA advisory text, or fix commit
itself. It does **not** mean the underlying vulnerable code path is unknown
to the model: Rails and libvips source, docs, and pre-fix commit history are
exactly the kind of public repository content that ordinarily enters
pretraining well before any CVE is filed against it. That distinction is
what the hint ladder actually measures (does the agent reconstruct the
weakness from first principles / analogy, vs. recall a familiar-looking
diff) — a pre-disclosure cutoff bounds the *second* kind of contamination
risk, not the first, and CIT-271's harness needs to keep that separate when
interpreting a hint-level-0 success.

**Jev is the harder case.** No model card, blog post, or docs page found
states a training cutoff. Jev's public launch (2026-09-27 per TypeSafe's own
post, see discrepancy note above) postdates both the CVE disclosure
(2026-07-29) and the technical-details release (2026-08-28) by weeks — but a
launch date bounds nothing about training-data recency in either direction
(a model can ship in September on a March data cutoff, or vice versa with a
late data refresh). So this is not evidence either way about whether Jev's
training data includes CVE-2026-66066; it only establishes that a cutoff
claim can't be checked at all right now. Concretely: **Jev's blindness on
this CVE is unknown and cannot be assumed.** That's a weaker claim than "not
blind," but it's the one the evidence supports, and it's enough on its own
to caveat CIT-275/276. This doesn't block the Sonnet/Opus side of the
experiment, but it does mean:

- CIT-275/276 (Jev fixture runs, trace scoring) cannot claim Jev's high/low
  vector was produced without CVE-2026-66066 knowledge. The negative control
  (fixture-negative-control.json) partially mitigates this — a model that
  flags *everything* high isn't discriminating — but it doesn't establish
  blindness on the positive case.
- If TypeSafe publishes a cutoff later (or answers directly), update this
  table before treating any CIT-275/276 result as evidence about detection
  capability rather than possibly-memorized recall.

## CIT-274: expected Jev vector

**Noul schema, verified against [docs.typesafe.ai/api](https://docs.typesafe.ai/api):**
a `noul` question takes `type`, `instructions`, and an optional `criteria`
object (`{true, false}` — free-text descriptions of what a yes/no answer
means). The draft fixture's `questions.json` uses only `type`/`instructions`,
both confirmed real fields; `criteria` is available but unused, which is
valid per the docs (optional). No OWASP-specific fields exist in the API —
category semantics live entirely in `instructions` text, as the draft
already assumed. `questions.json` is carried over unchanged into this
directory.

**Ground truth for the active-storage fixture, decided before any run:**
the public advisory (used here to build the answer key, not exposed to
whatever the fixture's own `state.diff_items`/`files` show a test subject)
maps CVE-2026-66066 to **CWE-1188, Initialization of a Resource with an
Insecure Default** — Active Storage did not disable libvips's
unfuzzed/untrusted-input loaders by default.

| Category | Draft | Decided | Why |
| --- | --- | --- | --- |
| a02 security misconfiguration | high | **high** (ratified) | Direct CWE-1188 match: insecure default / missing hardening step. |
| a03 software supply chain | high | **ambiguous** (downgraded) | libvips isn't compromised or unvetted — the flaw is Rails' own configuration of a legitimate dependency, not a supply-chain integrity failure. Defensible but weaker than a02's direct match. |
| a06 insecure design | ambiguous | **ambiguous** (kept) | Accepting untrusted uploads into a native image library without an operation allowlist is a threat-model gap (same class as ImageTragick, 2016 — the hint ladder's own level-2 analogy), but overlaps conceptually with a02 enough that forcing a split would overstate how sharp the category boundary is. |
| a05 injection | (not in draft) | **ambiguous** (added) | A crafted file is untrusted data driving unintended native code execution — injection-shaped, even though OWASP's Injection category is normally scoped to command/SQL/query interpretation rather than parser/memory-safety bugs. Worth tracking as a plausible grader false-positive path. |
| a01, a04, a07, a08, a09, a10 | low | **low** (kept) | No access-control/SSRF, cryptography, authentication, logging, or fail-open-exception-handling mechanism is described in the advisory; a08 in particular would just double-count a02/a06 if included. |

Full per-category rationale is recorded in `expected.rationale` in
[`fixture-active-storage.json`](./CIT-265/fixture-active-storage.json)
(also covers the negative control). `expected.decided` is now `true` in both
fixture files in [`docs/investigations/CIT-265/`](./CIT-265/); `state` in
each remains an explicit placeholder pending CIT-270 (active-storage case)
and CIT-272 (negative control) — filling it in is CIT-275's job, not this
pass's.
