## What reaches report.py from normalize()

normalize() returns one of two things: `None`, or a cleaned dict. Every valid dict has the same keys, `ident, person, worth, moment, variety, group`, and `gauge` has been removed. In practice there are five kinds of line:

| # | Line type | How it arises | What report.py must do |
|---|---|---|---|
| 1 | **`None` (dropped)** | `person` starts with `"test-"`, or the timestamp is below `1700000000` | Skip it entirely: no totals, no counts, no group buckets. Optionally count it as "filtered" for a diagnostics line. Don't re-apply the test-/epoch filters; those belong to transform. |
| 2 | **`group == "retail"`** | `variety` is 1 or 4 | Add it to the retail bucket. Treat 1 and 4 as one group; don't split them back apart by `variety` in the summary unless a per-variety breakdown is wanted. |
| 3 | **`group == "food"`** | `variety` is 2 | Add it to the food bucket. |
| 4 | **`group == "travel"`** | `variety` is 7 | Add it to the travel bucket. |
| 5 | **`group == "other"`** | Any other `variety`, including unexpected or garbage values | Add it to the other bucket. It's a real record, not an error, so it counts toward the grand totals. |

## Rules for every non-None record
- **Group by `group` only.** Never work out the group from `variety` in report.py, so there's a single source of truth for the mapping.
- **Use `worth` exactly as given.** It's already scaled by gauge and rounded to 2dp. Don't rescale it, and don't try to, because `gauge` isn't in the record. Sum the raw floats and round only the final totals to 2dp, so rounding errors don't add up per row.
- **`moment` is an int epoch** that's already ≥ 1700000000. Use it for date ranges, first/last timestamps or per-day bucketing. It needs no validation.
- **`ident` / `person`** are for counts: rows per group, and distinct persons if needed. `person` will never start with `test-`.
