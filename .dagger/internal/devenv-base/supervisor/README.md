# Dispatch-window supervisor (CIT-443)

One Render Cron Job per zone. Each run asks a headless `claude`, holding only
the toolbox's read-only tools, what it would do with that zone's dispatch
window, and fails unless a decision comes back.

```
Render cron (one per zone) ──▶ supervisor.sh
                                 │ pass-cli: CLAUDE_CODE_OAUTH_TOKEN
                                 ▼
                               claude -p  ──MCP, Bearer TOOLBOX_TOKEN──▶ toolbox
                                 │                                        (read-only tools)
                                 ▼
                               SUPERVISOR_HEARTBEAT: … decision=…  (the run's record)
```

This is the first slice and it is **dry run only**: no `host_start`, no
`host_stop`, no writes to Linear. It exists to get the decisions right before
anything acts on them.

## Why it cannot act

Three things at once, because an allowlist that fails open is exactly the
broken instrument this repo keeps writing principles about:

- only the read-only tools are in `--allowedTools`;
- every tool that starts, stops, deletes or dispatches is named in
  `--disallowedTools`, along with `Bash`, the editing tools, `WebFetch` and
  `Task` — with `Bash` the model could reach the toolbox over `curl` and
  route around the list entirely;
- `--strict-mcp-config` keeps any other MCP server out of the run.

`test_supervisor.sh` asserts all three against the packaged image, and that
the bearer token travels in a 0600 file rather than in `claude`'s argv.

## The heartbeat

The last line of a successful run is:

```
SUPERVISOR_HEARTBEAT: zone=<zone> host=<state> work=<yes|no|unknown> decision=<boot|gate|extend|stop|report|nothing> why=<a few words>
```

A run that produces prose without that line fails, as does one where `claude`
itself exits nonzero. A job that dies early reaps nothing and reports
nothing, which otherwise looks identical to a window where there was nothing
to do — so silence is never success.

## Secrets

| Where | What | Why |
| --- | --- | --- |
| Render env var, `sync: false` | `PROTON_PASS_PERSONAL_ACCESS_TOKEN` | logs `pass-cli` in, same as `devpod-keepalive` |
| Render env var, `sync: false` | `TOOLBOX_TOKEN` | **copied by hand from the toolbox Render service's env vars** — it was generated by Render and is not in Proton Pass |
| `supervisor.env` | `CLAUDE_CODE_OAUTH_TOKEN` | resolved from `pass://tidelands.dev/agent/…` at run time |

## Adding a zone

1. Publish the image: it goes out as `ghcr.io/null-hype/devenv-supervisor:sha-<commit>`
   whenever `supervisor/**` (or the shared Dagger chain) changes on `main`.
2. Uncomment the block in `render.yaml`, once per zone, and set `name`,
   `schedule` (the team's midnight expressed in UTC) and `SUPERVISOR_ZONE`.
   Pin the image digest, as the keepalive service does.
3. Set the two Render env vars on the new service.

Windows open *before* midnight, not at it: a delegation webhook that arrives
while the host is still booting lands on nothing and is gone.

## Iterating

`claude -p` reads `prompt.md`, so changing what the supervisor considers is a
prompt change plus a republish — no logic to rewrite. Kick a run instead of
waiting for the schedule:

```sh
bash .dagger/internal/devenv-base/.devcontainer/trigger-render-cron.sh
```

(point it at the supervisor's own cron job id).

Run the stub tests, which need neither network nor credentials:

```sh
bash .dagger/internal/devenv-base/supervisor/test_supervisor.sh
dagger -m .dagger/internal/devenv-base call check-supervisor
```

## What comes next

Per CIT-443, in order: the VM's own deadline and idle stop (the control that
trusts none of this), the agent's lease file so "is work being done" stops
guessing, the liveness gate from `check-linear-agent-webhook-live.sh` wired
into a real boot, and only then write tools for the supervisor itself.

Continuity — a resumed session per zone with Remote Control, so the
supervisor remembers why yesterday failed and can be talked to mid-window —
is deliberately not here yet. `LinearTriageAgent` in `main.go` records that a
restic + `claude --resume` cron job was tried for a similar job and replaced
by a disposable container; that trade is worth revisiting once the decisions
stop changing every run, not before.
